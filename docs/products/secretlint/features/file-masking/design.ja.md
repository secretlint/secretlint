# ファイルのマスクの設計

[English](design.md)

## このドキュメントについて

このドキュメントは、[Secretlint](../../product.ja.md)の[ファイルのマスク](requirements.ja.md)を`mask-result`フォーマッターでどう実現しているかを説明する。

### 対象読者

`mask-result`フォーマッター、またはフォーマッターが受け取るデータを変更する人とエージェント。

### 前提知識

この機能のRequirementsと、[結果の出力](../result-output/requirements.ja.md)のRequirements。後者は、フォーマッターの選び方と、そのテキストの出力のされ方を説明している。

### このドキュメントで扱わないこと

フォーマッターの読み込み方と、出力の書き出し方。ルールがメッセージの範囲を決める方法。

## 実装方針

`mask-result`は、`@secretlint/formatter`にあるSecretlint自身のフォーマッターである。
ほかのフォーマッターと同じように、すべてのファイルのlintの結果を受け取り、マスクした内容を1つのテキストとして返す。

フォーマッターはlintの結果ごとに、フォーマッターのオプションの`getSource`を結果のファイルパスで呼んで、ファイルの内容を取得する。
次に、各メッセージの範囲を同じ長さの`*`に置き換える。内容の長さが変わらないので、ほかのメッセージの範囲は正しいままになる。
マスクした内容は、結果の順に区切りなしでつなげる。

フォーマッターは、結果の内容の種類がバイナリの場合と、内容が取得できない場合にエラーを投げる。内容が取得できない場合とは、`getSource`がないか、`undefined`を返す場合である。
空文字列は内容なので、空のファイルは空のテキストにマスクされ、エラーにはならない。

### 内容の取得元

`mask-result`はすべてのファイルを出力するので、メッセージのあるファイルだけでなく、lintしたすべてのテキストファイルの内容が必要になる。
フォーマッターが`mask-result`の場合、エンジン（`@secretlint/node`）は各ファイルを文字列として読み、その文字列をlintし、`getSource`のために保持する。
フォーマッターがマスクする内容は、ルールが検査した文字列そのものなので、ファイルを2回読むことはない。

STDINの内容では、`getSource`は渡された文字列を返す。

### 設定のメッセージ

エンジンは、設定の問題を表示するために、設定ファイルについての結果をlintの結果に加えることがある。
その結果は内容を持たないので、フォーマッターが`mask-result`の場合、エンジンはそれを加えない。

## アーキテクチャ・シーケンス図

図は不要である。フォーマッターはlintの結果をテキストに変換する1つの関数であり、その前後の流れは結果の出力の流れである。

## データモデル・ER 図

フォーマッターは、lintの結果の`sourceContentType`と各メッセージの`range`、そして`getSource`から得た内容を使う。データは追加しない。

## API・インターフェース

フォーマッターのインターフェースは、ほかのフォーマッターと同じである。lintの結果の一覧とフォーマッターのオプションを受け取り、出力のテキストを返す。
利用者は`--format=mask-result`で選ぶ。
`loadFormatter`を通してフォーマッターを呼ぶプログラムは、`getSource`を渡す必要がある。渡さない場合、フォーマッターは最初の結果でエラーを投げる。

## 外部サービスとの連携方式

なし。

## データの取り扱い設計

lintしたすべてのファイルの内容を、フォーマッターが返るまで文字列としてメモリに保持し、つなげて出力を作る。
出力は、コマンドが標準出力か`--output`のファイルへ書き出す。lintしたファイルと同じパスを指定すると、ファイルはマスクした内容に置き換わる。

## 認証認可に関する特記事項

なし。この機能は、コマンドの利用者が読み書きできるファイルを読み書きする。

## セキュリティ上の留意事項

[内容の取得元](#内容の取得元)で説明したとおり、フォーマッターはルールが検査した文字列をマスクするので、どのルールも検査していない内容が出力されることはない。
フォーマッターは、マスクできないファイルが1つでもあるとテキストを返す前にエラーを投げるので、一部のファイルだけが出力されることはない。

## 検討した代替手段

### `mask-result`でもファイルを共有バッファに読み、すべてデコードする

エンジンは、ほかのフォーマッターと同じようにファイルをバイト列で読み、lintのあとにすべてのファイルをデコードする。
採用しなかった理由は、`mask-result`はどのみちすべての内容を文字列として必要とするためである。最初から文字列として読むほうが単純で、内容の経路が1つになる。

### バイナリファイルをエラーにせずスキップする

フォーマッターがバイナリファイルを出力から除いてテキストファイルだけをマスクするので、多くのファイルを`mask-result`でlintしても、画像1つのために失敗しなくなる。
採用しなかった理由は、`mask-result`は基本的に1つのファイルに使うものだからである。バイナリファイル1つの場合、スキップすると出力が空になり、同じパスへの`--output`でファイルが空のファイルに置き換わる。
